2. Deep Dive Analysis

A. PDFKit (Marvel's Team - Current)

Architecture

JavaScript → PDFKit API → wkhtmltopdf → WebKit Engine → PDF

Pros:

  • Lightweight (~5MB memory per generation)
  • Fast for simple documents (50-200ms)
  • Good for programmatic PDFs (invoices, receipts)
  • Low CPU usage

Cons (Critical Issues):

  • Text Measurement Inaccuracies - Root cause of blank pages
  • Outdated WebKit (2015 version) - Poor modern CSS support
  • JavaScript Rendering - Nearly non-existent
  • Character Encoding - Fails with Japanese, Chinese, German special chars
  • Dynamic Content - Cannot handle forms, charts properly
  • No longer maintained - Last update 2021

Edge Case Analysis - PDFKit

Issue Status Impact
Long text wrapping ❌ FAILS Text overlaps
Blank page generation ❌ FREQUENT Poor user experience
Footer recognition ❌ INCONSISTENT Missing footers
Special characters (CJK) ❌ FAILS Unreadable reports
Chart/table overflow ❌ CREATES BLANK PAGES Layout breaks
Multi-column layouts ❌ POOR Design limitations

Verdict: ❌ NOT RECOMMENDED - Too many production issues

B. Puppeteer (Reportica Team - Current)

Architecture

JavaScript → Puppeteer API → Headless Chrome → Blink Engine → PDF

Pros:

  • Full JavaScript execution (React, Vue, Angular support)
  • Modern CSS (Grid, Flexbox, animations)
  • Accurate rendering (99% match to browser)
  • Active development (Google maintains)
  • Excellent Unicode support (all languages)
  • Handles dynamic content perfectly

Cons:

  • Heavy resource usage (~150MB per Chrome instance)
  • Slower (~1-3 seconds per PDF)
  • Page break control - Requires manual CSS
  • Header/footer customization - Limited API
  • Font embedding - Requires system fonts or @font-face

Edge Case Analysis - Puppeteer

Issue Status Solution
Long text wrapping ✅ WORKS Native browser engine
Blank page generation ✅ RARE CSS: break-inside: avoid
Footer recognition ⚠️ MANUAL displayHeaderFooter API
Special characters ✅ PERFECT Full Unicode support
Chart/table overflow ✅ WORKS CSS: page-break-inside: avoid
Multi-column layouts ✅ PERFECT CSS columns work natively

Verdict: ✅ RECOMMENDED - Best for complex layouts with proper optimization

E. html-pdf-node (Puppeteer Wrapper)

Architecture

JavaScript → html-pdf-node API → Puppeteer → Chromium → PDF

Pros:

  • ✅ Simpler API than raw Puppeteer
  • ✅ Automatic browser management
  • ✅ All benefits of Chromium rendering
  • ✅ Promise-based (async/await friendly)
  • ✅ Smaller learning curve

Cons:

  • ⚠️ Same performance as Puppeteer (~2s)
  • ⚠️ Same memory usage (~150MB)
  • ⚠️ Less control than raw Puppeteer
  • ⚠️ Dependency on Puppeteer updates

Code Example:

const htmlPdf = require('html-pdf-node');

let options = { format: 'A4' };
let file = { content: "<h1>Welcome</h1><p>This is a test</p>" };

htmlPdf.generatePdf(file, options).then(pdfBuffer => {
  console.log("PDF Buffer:", pdfBuffer);
});

Verdict: ✅ GOOD - Easier than Puppeteer but same performance characteristics

F. jsPDF (Pure JavaScript)

Architecture

JavaScript → jsPDF API → Canvas/SVG → Pure JS PDF Generation

Pros:

  • ✅ Works in browser (client-side generation)
  • ✅ No server-side dependencies
  • ✅ Very lightweight (~200KB)
  • ✅ Fast for simple documents (~100ms)
  • ✅ Good for forms, invoices, certificates
  • ✅ Plugin ecosystem (autotable, svg, html)

Cons:

  • ❌ HTML support is LIMITED (via html2canvas)
  • ❌ Complex layouts are difficult
  • ❌ No CSS parsing (must position manually)
  • ❌ Poor text wrapping
  • ❌ Limited font support
  • ❌ Not suitable for complex reports

Code Example:

const { jsPDF } = require('jspdf');

const doc = new jsPDF();
doc.text("Hello world!", 10, 10);
doc.save("output.pdf");

// With HTML (limited support)
doc.html(document.body, {
  callback: function (doc) {
    doc.save('output.pdf');
  }
});

Edge Case Analysis - jsPDF

G. pdfmake (Declarative)

Architecture

JavaScript → JSON Definition → pdfmake Engine → PDF

Pros:

  • ✅ Declarative JSON-based layout
  • ✅ Works in browser and Node.js
  • ✅ Good table support
  • ✅ Styling via style definitions
  • ✅ Headers/footers with page numbers
  • ✅ Watermarks and background layers
  • ✅ Fast (~200-500ms)

Cons:

  • ❌ NO HTML support (must convert to JSON)
  • ❌ Learning curve for layout system
  • ❌ Complex layouts require manual positioning
  • ❌ Limited CSS-like styling
  • ⚠️ Not suitable for HTML-based reports

Code Example:

const pdfMake = require('pdfmake/build/pdfmake');

const docDefinition = {
  content: [
    { text: 'This is a header', style: 'header' },
    { text: 'This is a paragraph' },
    {
      table: {
        body: [
          ['Column 1', 'Column 2'],
          ['Value 1', 'Value 2']
        ]
      }
    }
  ],
  styles: {
    header: { fontSize: 18, bold: true }
  }
};

pdfMake.createPdf(docDefinition).download();

Verdict: ✅ GOOD - Excellent for structured documents, but can't use HTML

Aspose.PDF Service (Java)

import com.aspose.pdf.*;
import com.aspose.pdf.HtmlLoadOptions;

public class PDFGeneratorService {
    
    public byte[] generatePDF(String html, PDFOptions options) {
        long startTime = System.currentTimeMillis();
        
        try {
            // Load HTML with options
            HtmlLoadOptions htmlOptions = new HtmlLoadOptions();
            htmlOptions.setPageInfo(new PageInfo());
            htmlOptions.getPageInfo().setMargin(
                new MarginInfo(40, 40, 40, 40)
            );
            
            // Handle fonts for special characters
            htmlOptions.setLoadFormat(LoadFormat.Html);
            htmlOptions.setUseSystemFontsForFontFallback(true);
            
            // Create document from HTML
            Document pdfDocument = new Document(
                new ByteArrayInputStream(html.getBytes("UTF-8")), 
                htmlOptions
            );
            
            // Optimize for size
            pdfDocument.optimize();
            
            // Add metadata
            pdfDocument.getInfo().setTitle(options.getTitle());
            pdfDocument.getInfo().setCreator("MFS Report Generator");
            
            // Convert to bytes
            ByteArrayOutputStream outputStream = 
                new ByteArrayOutputStream();
            pdfDocument.save(outputStream, SaveFormat.Pdf);
            
            long duration = System.currentTimeMillis() - startTime;
            logger.info("PDF generated in {}ms", duration);
            
            return outputStream.toByteArray();
            
        } catch (Exception e) {
            logger.error("PDF generation failed", e);
            throw new PDFGenerationException(e);
        }
    }
}

Optimized Puppeteer Service (Node.js) - Alternative

const genericPool = require('generic-pool');
const puppeteer = require('puppeteer');

const browserPool = genericPool.createPool({
  create: async () => {
    return await puppeteer.launch({
      headless: true,
      args: [
        '--no-sandbox',
        '--disable-setuid-sandbox',
        '--disable-dev-shm-usage',
        '--disable-gpu',
        '--single-process'
      ]
    });
  },
  destroy: async (browser) => {
    await browser.close();
  }
}, {
  min: 2,    // Keep 2 instances warm
  max: 10,   // Max 10 instances
  testOnBorrow: true
});

async function generatePDF(html, options) {
  const startTime = Date.now();
  const browser = await browserPool.acquire();
  
  try {
    const page = await browser.newPage();
    
    // Block unnecessary resources (speeds up 2x)
    await page.setRequestInterception(true);
    page.on('request', (req) => {
      if (['image', 'stylesheet', 'font']
          .includes(req.resourceType())) {
        req.continue();
      } else {
        req.abort();
      }
    });
    
    await page.setContent(html, { 
      waitUntil: 'networkidle0' 
    });
    
    const pdf = await page.pdf({
      format: 'A4',
      printBackground: true,
      margin: { 
        top: '20mm', 
        bottom: '20mm', 
        left: '15mm', 
        right: '15mm' 
      },
      ...options
    });
    
    await page.close();
    console.log(`PDF generated in ${Date.now() - startTime}ms`);
    return pdf;
    
  } finally {
    await browserPool.release(browser);
  }
}
