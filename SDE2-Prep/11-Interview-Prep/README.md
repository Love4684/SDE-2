## Part 1: Coding Round Strategy

### During the Interview
1. **Read the problem carefully** — repeat back to interviewer
2. **Ask clarifying questions** — input size, edge cases, constraints
3. **Discuss brute force** — show you can think step by step
4. **Optimize** — discuss approach before coding
5. **Code clean** — meaningful variable names, modular
6. **Dry run** — trace through a small example
7. **Complexity analysis** — time and space, proactively

### Common Mistakes to Avoid
- Jumping to code without discussing approach
- Not handling edge cases (empty input, single element, duplicates)
- Using global variables
- Not testing your solution
- Overcomplicating the solution

## Part 2: Machine Coding Round

### What It Is
- 60-90 minute round where you build a working system
- Tested on: OOP design, code organization, extensibility, SOLID
- Usually no framework — plain Java/console app

### Strategy
| Time | Activity |
|------|----------|
| 0-10 min | Read problem, clarify, identify entities |
| 10-20 min | Design classes, interfaces, relationships |
| 20-60 min | Implement core functionality |
| 60-75 min | Handle edge cases, add extensibility |
| 75-90 min | Test, clean up, prepare to explain |

## Part 3: Behavioral / HR Round

### STAR Method
- **S**ituation — Set the context
- **T**ask — What was your responsibility
- **A**ction — What you did (focus here)
- **R**esult — Measurable outcome

### Prepare Stories For (Use Your SHL/Samsung Experience)
| Theme | Your Possible Story |
|-------|-------------------|
| Leadership / Ownership | Led authentication architecture at SHL |
| Conflict Resolution | Disagreed on technical approach with team |
| Challenging Bug | One of those 100+ production incidents at SHL |
| Tight Deadline | Critical release at Samsung R&D |
| Failure & Learning | A production issue you caused and fixed |
| Cross-team Collaboration | Working across teams at SHL |
| Mentoring | Helping junior developers |
| Ambiguity | Feature with unclear requirements |
| Trade-off Decision | Chose pragmatic solution over ideal |
| Process Improvement | Reduced repeat incidents → 99.9% uptime |

### Common Behavioral Questions
1. Tell me about yourself. (2-minute pitch)
2. Why are you leaving your current role?
3. Tell me about a time you had a disagreement with a teammate.
4. Describe a challenging technical problem you solved.
5. Tell me about a time you failed. What did you learn?
6. How do you prioritize when you have multiple urgent tasks?
7. Tell me about a time you took ownership beyond your role.
8. How do you handle working with ambiguous requirements?
9. Describe a time you improved a process or system.
10. Where do you see yourself in 3-5 years?
